# Sprint Plan — Hotel CRM

Всего: 18 задач, 5 спринтов, ~10 недель разработки.
Методология: каждый спринт = 2 недели, заканчивается демо и ретро.

---

## Sprint 0 — Foundation (Недели 1–2)
**Цель:** Работающий скелет приложения. Агент может запустить `npm run dev` и увидеть страницу.

| ID  | Задача                          | Приоритет | Агент-роль       |
|-----|---------------------------------|-----------|------------------|
| T01 | Инициализация проекта + схема БД | 🔴 HIGH   | Backend/DB agent |
| T02 | Auth модуль (JWT + роли)         | 🔴 HIGH   | Backend agent    |
| T04 | UI Design System (компоненты)    | 🟡 MED    | Frontend agent   |

**Definition of Done Sprint 0:**
- [ ] `npm run dev` работает без ошибок
- [ ] PostgreSQL схема создана, миграции применены
- [ ] `/api/v1/auth/login` возвращает JWT
- [ ] 3 базовых компонента в Storybook (Button, Input, Card)
- [ ] Все 4 роли проверяются в тестах

**Зависимости:** Нет. Можно запускать параллельно T01 (backend) и T04 (frontend).

---

## Sprint 1 — Core Entities (Недели 3–4)
**Цель:** Можно создать гостя, посмотреть его профиль, создать бронирование.

| ID  | Задача                          | Приоритет | Агент-роль         |
|-----|---------------------------------|-----------|---------------------|
| T03 | Карточка гостя (CRUD)            | 🔴 HIGH   | Backend agent       |
| T05 | Dashboard главная страница       | 🟡 MED    | Frontend agent      |
| T06 | Модуль бронирований              | 🔴 HIGH   | Full-stack agent    |

**Definition of Done Sprint 1:**
- [ ] CRUD /api/v1/guests работает, поиск по имени/телефону/email
- [ ] /api/v1/bookings поддерживает полный жизненный цикл (5 статусов)
- [ ] Конфликт дат при бронировании блокируется на уровне API
- [ ] Dashboard отображает реальные данные (без заглушек)
- [ ] E2E тест: создать гостя → создать бронирование → сменить статус

**Зависимости:** Sprint 0 завершён (T01 обязателен — схема БД).

## Sprint 2 — CRM Features (Недели 5–6)
**Цель:** Менеджер может вести историю общения с гостем и сегментировать базу.

| ID  | Задача                          | Приоритет | Агент-роль         |
|-----|---------------------------------|-----------|---------------------|
| T07 | История взаимодействий (timeline)| 🔴 HIGH   | Full-stack agent    |
| T11 | Глобальный поиск + фильтры       | 🟡 MED    | Full-stack agent    |
| T12 | Сегментация гостей (теги/группы) | 🟡 MED    | Backend agent       |
| T15 | RBAC детальный                   | 🔴 HIGH   | Backend agent       |

**Definition of Done Sprint 2:**
- [ ] Лог взаимодействий (5 типов) с фильтрами и экспортом CSV
- [ ] Глобальный поиск < 200ms, fuzzy по всем полям гостя
- [ ] Автосегменты пересчитываются (VIP, потерянный)
- [ ] Permission matrix задокументирована и покрыта тестами
- [ ] Audit log на все мутирующие операции

**Зависимости:** T03 (guests API), T02 (RBAC infrastructure).

## Sprint 3 — Marketing & Realtime (Недели 7–8)
**Цель:** Можно отправить рассылку сегменту гостей и получать уведомления в реальном времени.

| ID  | Задача                          | Приоритет | Агент-роль         |
|-----|---------------------------------|-----------|---------------------|
| T08 | Email-маркетинг кампании         | 🟡 MED    | Full-stack agent    |
| T09 | Уведомления (WebSocket)          | 🟡 MED    | Backend agent       |
| T10 | Отчёты и аналитика               | 🟡 MED    | Full-stack agent    |

**Definition of Done Sprint 3:**
- [ ] Кампания создана → отправлена через Resend → статистика в UI
- [ ] Drag-n-drop сегменты для кампаний
- [ ] WebSocket уведомления доставляются в < 1s
- [ ] Bell icon с unread counter работает
- [ ] Отчёты: загруженность, LTV, эффективность кампаний
- [ ] Экспорт PDF/Excel работает

**Зависимости:** T12 (сегменты), T06 (bookings для отчётов).

**Цель:** Система готова к продакшену. Интеграции, PWA, мониторинг.

**Зависимости:** Все предыдущие спринты завершены.

## Параллельность задач (рекомендации для мульти-агентной работы)

```
Sprint 0:  [T01 backend] || [T04 frontend]  — независимы
Sprint 1:  [T03 backend] || [T05 frontend]  — T06 после T01+T03
Sprint 2:  [T15 backend] || [T11+T12 full]  — T07 после T15
Sprint 3:  [T09 backend] || [T08+T10 full]  — независимы внутри спринта
Sprint 4:  [T13 backend] || [T14+T16 frontend] || [T17+T18 backend]
```

**Ветки:** каждая задача — отдельная ветка `feat/task-id-slug`.
Мёрж только через PR с ревью (человек или review-агент).
